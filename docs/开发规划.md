# Loophrase 开发规划

> 基于《Loophrase-MVP-需求分析.md》，按阶段（Phase）→ 冲刺（Sprint）→ 任务（Task）拆解，给出可执行的开发路径。

## 0. 技术栈确认与项目初始化

| 层级 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Expo (SDK 52+) + React Native + TypeScript | 使用 Expo Development Build，以支持原生媒体模块 |
| 导航 | expo-router (file-based) | 今日/素材库/编辑器/播放器/复习/设置 六大页面 |
| 媒体 | expo-video + expo-audio + expo-av(legacy 兼容) | 单句循环、变速、录音；必要时写 Config Plugin |
| 存储 | expo-file-system + expo-sqlite (next) + expo-secure-store | 媒体文件 + 结构化数据 + 凭据 |
| 后端 | Supabase (Auth/Postgres/Storage/Edge Functions) | 可选同步；离线优先 |
| 转写 | Provider 抽象层 + Whisper 兼容 Worker | 可替换；只传音轨 |
| 状态管理 | Zustand + React Query (同步) | 轻量、离线友好 |
| 样式 | Tamagui 或 NativeWind (Tailwind) | 主题/字号可访问性 |
| 测试 | Jest + React Native Testing Library + Detox (E2E 可选) | |

**初始化任务清单：**

1. 创建 Monorepo 结构（`apps/mobile`、`packages/shared`、`supabase`、`transcribe-worker`）。
2. `expo prebuild` 生成原生项目，建立 iOS/Android 真机测试基线。
3. 配置 ESLint + Prettier + TypeScript strict + Husky pre-commit。
4. 建立 CI（GitHub Actions）：lint → typecheck → test → build（EAS Build）。
5. 初始化 Supabase 项目与本地 schema 迁移仓库。

**数据库 Schema（初版）：**

```sql
-- media_project
CREATE TABLE media_project (
  id            TEXT PRIMARY KEY,
  title         TEXT NOT NULL,
  local_uri     TEXT NOT NULL,
  duration_ms   INTEGER NOT NULL,
  source_type   TEXT NOT NULL,            -- 'video' | 'audio'
  has_audio     INTEGER DEFAULT 1,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);

-- subtitle_source
CREATE TABLE subtitle_source (
  id          TEXT PRIMARY KEY,
  project_id  TEXT NOT NULL REFERENCES media_project(id) ON DELETE CASCADE,
  type        TEXT NOT NULL,              -- 'srt' | 'vtt' | 'transcription'
  language    TEXT DEFAULT 'en',
  version     INTEGER DEFAULT 1,
  raw_content TEXT,
  created_at  INTEGER NOT NULL
);

-- segment（练习切片）
CREATE TABLE segment (
  id           TEXT PRIMARY KEY,
  project_id   TEXT NOT NULL REFERENCES media_project(id) ON DELETE CASCADE,
  order_index  INTEGER NOT NULL,
  start_ms     INTEGER NOT NULL,
  end_ms       INTEGER NOT NULL,
  text         TEXT NOT NULL,
  confidence   REAL,                       -- 转写置信度，字幕来源为 NULL
  skip_type    TEXT,                        -- 'intro' | 'outro' | 'music' | NULL
  source       TEXT NOT NULL,             -- 'subtitle' | 'transcription' | 'manual'
  status       TEXT NOT NULL,             -- 'pending' | 'confirmed'
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);

-- practice_attempt
CREATE TABLE practice_attempt (
  id            TEXT PRIMARY KEY,
  segment_id    TEXT NOT NULL REFERENCES segment(id) ON DELETE CASCADE,
  mode          TEXT NOT NULL,            -- 'blind_listen' | 'shadow'
  result        TEXT,                     -- 'understood' | 'not_smooth' | 'mastered'
  recording_uri TEXT,
  duration_ms   INTEGER,
  created_at    INTEGER NOT NULL
);

-- review_schedule
CREATE TABLE review_schedule (
  segment_id     TEXT PRIMARY KEY REFERENCES segment(id) ON DELETE CASCADE,
  state          TEXT NOT NULL,           -- 'new' | 'practicing' | 'due' | 'mastered'
  due_at         INTEGER NOT NULL,
  interval_days  INTEGER DEFAULT 0,
  review_count   INTEGER DEFAULT 0,
  updated_at     INTEGER NOT NULL
);
```

### Sprint A2：素材导入与字幕解析

| 任务 | 详情 | 对应需求 |

| 任务 | 详情 | 对应需求 |

| A3-5 切片编辑器 UI | 视频预览 + 时间轴 + 切片卡片列表 + 编辑操作 | §7 |

### Sprint A4：精练播放器（离线核心）

| 任务 | 详情 | 对应需求 |
| --- | --- | --- |
| A4-1 单句循环播放 | 基于 segment 的 start/end 精确循环；跳上/下句 | FR-P01 |
| A4-2 变速不变调 | 0.75× / 1× / 1.25×；使用播放器原生 timePitch | FR-P02 |
| A4-3 字幕模式切换 | 英文 / 中文(如有) / 双语 / 隐藏 四模式；盲听一键显答案 | FR-P03/P06 |
| A4-4 播放缓冲 | 切片前后预留 0.2s/0.4s；可在设置调整 | FR-S06 |
| A4-5 循环延迟优化 | 预加载相邻切片，目标 <300ms 跳转延迟 | §10 性能 |

> **技术难点：** `expo-video` 循环精度。需要监听 `timeUpdate`，在到达 `endMs` 时 `seek(startMs)`。若精度不足，评估原生模块或使用 `expo-av` legacy 的 `setOnPlaybackStatusUpdate`。建立真机测试基准。

## 5. Phase C：数据驱动优化

> 基于 Phase B 的真实使用数据迭代，不在 MVP 前预先开发。

| 方向 | 触发条件 | 动作 |
| --- | --- | --- |
| 断句优化 | 切片修正率 > 30% | 调整断句权重；增加语速/停顿因子 |
| 片头片尾识别 | 用户频繁手动标记 | 引入 VAD / 音乐检测自动建议 |
| 复习节奏 | 复习完成率 < 60% | 优化提醒；调整每日新增上限与间隔 |
| 发音反馈 | 用户主动需求 | 词级对齐 + 节奏/停顿/重音多维反馈 |
| 离线转写 | 网络失败率高 | 评估 on-device 模型 |

## 6. 关键技术风险与应对

| 风险 | 影响 | 应对策略 |
| --- | --- | --- |
| 循环播放精度差 | 核心体验受损 | Phase A 即建立延迟基准；必要时写原生 Config Plugin 直连 AVFoundation/Media3 |
| 媒体格式兼容 | 导入失败 | 首版限定 H.264/AAC MP4 + MP3/M4A；真机测试矩阵 |
| 音频中断恢复 | 录音丢失/崩溃 | 全局 Audio Session 管理；中断监听 + 恢复提示 |
| 转写成本/隐私 | 商业与合规 | 按任务计量；只传音轨；24h 自动删除；可替换 Provider |
| 同步冲突 | 数据不一致 | 本地优先 + last-write-wins；关键字段用 `updated_at` |
