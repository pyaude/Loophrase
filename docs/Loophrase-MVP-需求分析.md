# 100LS 英语精练 App：MVP 需求分析

| 项目 | 内容 |
| --- | --- |
| 文档版本 | 0.1 |
| 产品阶段 | MVP |
| 目标平台 | iOS、Android |
| 目标语言 | 英语学习；界面使用简体中文 |
| 更新日期 | 2026-08-05 |

## 1. 背景与问题

100LS 的核心是以真实语料为单位，反复进行听力（Listening）与跟读输出（Speaking）。学习者真正的困难通常不在于“找到视频”，而在于：

1. 无法把一段视频快速拆成可练习的句子或意群。
2. 听不清连读、弱读、失爆和口语缩略，也无法将声音与文字对应。
3. 没有低摩擦的逐句循环、留白跟读和录音对比工具。
4. 练过的句子没有在遗忘前被再次调出，导致大量重复停留在单次刷量。

本产品将视频或音频转为**可编辑的虚拟练习切片**，再通过“盲听—核对—跟读—记录—间隔复习”的闭环，帮助学习者练习真实英语语流。产品不是影视内容平台，也不承诺以固定次数或固定天数保证学习结果。

## 2. 产品目标与非目标

### 2.1 MVP 目标

在不依赖自建影视片库的前提下，让用户能够在 15 分钟内完成一次有效训练：

> 导入一段自有或获授权素材 → 获得并修正句子切片 → 逐句听读和录音 → 标记困难句 → 在后续日期完成复习。

北极星指标：**用户每周完成至少 3 次、每次至少 10 分钟的有效句子练习。**

### 2.2 非目标

- 不提供或抓取 Netflix、YouTube、影视剧等第三方受版权保护内容。
- 不做社区动态、排行榜、课程市场、AI 陪聊或多语言学习。
- 不把“播放次数”“连续打卡天数”作为核心学习成效。
- 不在 MVP 中提供单一的“发音总分”或“像母语者程度”评分。
- 不把音乐歌词自动纳入学习语料；只有用户导入或已获授权的歌词素材才可练习。

## 3. 目标用户与使用场景

### 3.1 目标用户

| 用户 | 特征 | 核心需求 |
| --- | --- | --- |
| 自学成人（主目标） | 英语约 A2–B2；每天可投入 10–20 分钟 | 将喜欢的真实内容转为明确、可持续的听说训练。 |
| 有基础的影视学习者 | 经常看英文视频，但听力与口语脱节 | 快速循环难句、理解语流、模仿语调。 |
| 隐私敏感用户 | 不希望把视频与录音长期上传 | 原视频和录音默认留在本机；云端转写需明确同意。 |

### 3.2 典型场景

1. 用户导入 8 分钟访谈视频与英文字幕，系统生成约 60 个练习切片；用户用 15 分钟精练其中 5 句。
2. 用户导入无字幕的短视频，选择“云端生成转写”；系统仅上传提取后的音轨，返回待确认的句子切片。
3. 用户在通勤时打开“今日复习”，关字幕听 10 个到期句子，并对其中 3 句进行跟读录音。

## 4. 学习闭环与产品原则

### 4.1 单句练习闭环

```text
盲听 → 自评是否听懂 → 查看英文原文与语流提示 → 循环听读 → 录音对比
  → 关字幕复听/复述 → 标记掌握程度 → 在后续日期复习
```

### 4.2 设计原则

1. **以句块为单位，而非以视频播放次数为单位。** 每个练习单元要可独立定位、循环、录音和复习。
2. **本地优先。** 原视频、切片缓存和录音默认保存在设备；无网络也可学习已导入内容。
3. **AI 只给建议，用户保留最终编辑权。** 转写、断句和音乐跳过都必须可以修正。
4. **先识别，再模仿。** 先隐藏字幕盲听，再展示文本；避免学习者始终依赖翻译阅读。
5. **以延迟保留检验效果。** 复习优先调度“到期且未稳固”的句子，而非继续播放新内容。

## 5. MVP 范围

### 5.1 P0 功能清单

| 模块 | P0 功能 | 价值 |
| --- | --- | --- |
| 素材导入 | 导入本地 `MP4`、`MP3/M4A` 与 `SRT/VTT`；首版正式支持 H.264/AAC 的 MP4。 | 避开片库版权与内容采购问题。 |
| 转写与字幕 | 优先解析用户字幕；无字幕时可选择云端英文转写。 | 让无字幕素材也能进入练习闭环。 |
| 智能断句 | 基于字幕、标点、时长和停顿生成虚拟切片；支持手动合并、拆分与拖动边界。 | 获得可复读的最小练习单元。 |
| 非对白处理 | 根据连续无字幕/无语音区间建议跳过片头、片尾和纯音乐；用户可改为保留。 | 减少无效播放，防止音乐计入学习时长。 |
| 精练播放器 | 单句循环、前后句跳转、变速不变调、自动暂停留白、字幕显示模式切换。 | 支撑逐句听读。 |
| 跟读录音 | 原句播放后录音；可回放原音与本人录音；支持“没听懂”“没说顺”标记。 | 形成输出与自我纠错。 |
| 复习系统 | 困难句、未掌握句进入间隔复习；默认复习间隔为 1、3、7、14、30 天。 | 将高强度练习转为长期记忆。 |
| 今日页与统计 | 展示待复习句、当前素材进度、有效练习时长和无字幕听懂率。 | 告诉用户下一步做什么，而非只显示总时长。 |
| 账号与同步 | 可选登录；登录后同步素材元数据、切片、复习记录。原视频不参与同步。 | 支持换机与后续云端能力。 |

### 5.2 P1（验证 MVP 后）

- 更准确的音乐/人声分类与自动片头片尾识别。
- 词级卡拉 OK 高亮、波形视图和更细的语流规则标注。
- 对录音做节奏、停顿、重音和关键词遗漏的多维反馈。
- 离线转写语言包、云端录音备份、授权内容库。

## 6. 功能需求

### 6.1 素材与字幕

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-M01 | 用户可从文件或系统媒体库选择视频、音频和字幕文件。 | 选择一个受支持的视频与 SRT 后，可创建素材项目并进入处理状态。 |
| FR-M02 | 用户必须勾选“我拥有或获授权使用此素材”的确认项。 | 未确认时不可完成导入。 |
| FR-M03 | 系统优先使用用户导入的原语言字幕，不自动用机器翻译替代英文原文。 | 有 SRT/VTT 时，不触发转写任务。 |
| FR-M04 | 当没有字幕时，用户可主动选择云端转写，并查看上传范围、用途与自动删除期限。 | 用户未同意时，音轨不会离开设备；同意后仅上传提取的音频。 |
| FR-M05 | 原视频默认保存在本地；服务端只保存媒体元数据、切片、学习记录及用户主动备份的录音。 | 断网后，已导入视频和练习记录仍可访问。 |

### 6.2 转写与智能断句

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-S01 | 系统将字幕行或转写结果转换为带起止时间的虚拟练习切片，不生成重复的视频文件。 | 调整某切片时间边界不会产生新的媒体文件。 |
| FR-S02 | 默认建议的练习切片时长为 1–12 秒；过长台词按标点、连接词与停顿建议切为意群。 | 一条 20 秒的长句至少可被拆为两个可编辑候选片段。 |
| FR-S03 | 每个切片显示英文文本、起止时间、前后文索引、来源类型（字幕/转写）与待确认状态。 | 用户能判断切片来自何处并跳至前后句。 |
| FR-S04 | 用户可以合并相邻切片、拆分切片、拖动起止时间，并撤销最近一次编辑。 | 编辑后播放器、复习队列和统计均使用新边界。 |
| FR-S05 | 云端转写返回句级时间轴、可用的词级时间与置信信息；低置信片段标注为“建议核对”。 | 低置信片段不会被自动标记为可直接掌握。 |
| FR-S06 | 系统为切片前后各预留少量播放缓冲，默认前 0.2 秒、后 0.4 秒，可在设置中调整。 | 单句循环不会吞掉首个词或尾音。 |

### 6.3 非对白、片头和片尾

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-N01 | 连续无字幕且无识别语音的区间可被标记为“建议跳过”。 | 用户开启“跳过非对白”后，播放自动越过已标记区间。 |
| FR-N02 | 用户可在时间轴上把任何区间标为片头、片尾、纯音乐或保留。 | 手动标记优先级高于系统建议，并可撤销。 |
| FR-N03 | 有对白的配乐片段不得自动跳过。 | 系统仅标记为“背景音乐可能影响听辨”，仍保留在练习列表中。 |
| FR-N04 | 被跳过的片段不计入有效听力、复读次数或完成率。 | 学习统计中的有效时长不包含该区间。 |

### 6.4 精练播放器与跟读

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-P01 | 用户能播放当前切片、循环当前切片、跳转上一/下一切片。 | 连续点击循环不会离开当前时间范围。 |
| FR-P02 | 提供 `0.75×`、`1×`、`1.25×` 速度；降速时不改变音调。 | 听感可辨认为原声调高，且字幕时间轴保持同步。 |
| FR-P03 | 支持英文、中文（若用户自行提供或系统生成）、双语与无字幕四种显示模式。 | 切换无字幕后，媒体仍继续播放，用户可一键显示答案。 |
| FR-P04 | “回声跟读”模式按“播放原句 → 静音留白 → 开始录音 → 回放”的流程工作。 | 用户可以在同一切片下保存至少一条本地录音并与原音交替播放。 |
| FR-P05 | 用户可为切片标记“没听懂”“没说顺”“已掌握”。 | 标记会影响该切片的下一次复习时间。 |
| FR-P06 | 用户可从任意切片进入盲听：先隐藏文本，再显示英文答案。 | 无字幕听辨完成后，系统记录一次自评结果。 |

### 6.5 间隔复习与进度

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-R01 | 每个切片有 `new`、`practicing`、`due`、`mastered` 四种学习状态。 | 状态转移后在项目列表和今日页一致显示。 |
| FR-R02 | “没听懂”和“没说顺”默认安排至次日；“已掌握”按 3、7、14、30 天递进复习。 | 设备日期变化后，到期切片出现在今日页。 |
| FR-R03 | 今日页优先展示到期复习，再推荐不超过用户每日上限的新切片。 | 设置每日新增上限为 5 时，当日不会自动加入第 6 条新句。 |
| FR-R04 | 有效练习时长只统计对话切片的播放、盲听、录音和复习活动。 | 片头、片尾、纯音乐与后台静置不计入有效时长。 |

## 7. 信息架构与页面

| 页面 | 主要内容 | 主要动作 |
| --- | --- | --- |
| 今日 | 到期复习、今日新增、有效练习与无字幕听懂率 | 开始复习、继续上次素材。 |
| 素材库 | 本地项目、处理状态、最近学习进度 | 导入、删除、进入项目。 |
| 切片编辑器 | 视频时间轴、切片卡片、片头片尾/音乐标记 | 合并、拆分、拖动边界、标记跳过。 |
| 精练播放器 | 视频、当前字幕、循环与录音控制、掌握标记 | 盲听、跟读、录音、加入复习。 |
| 复习 | 到期句子队列与结果 | 听辨、跟读、自评。 |
| 设置与隐私 | 登录、同步、转写授权、音频上传记录与删除 | 修改偏好、删除云端数据。 |

## 8. 关键业务规则

### 8.1 切片规则

1. 切片由 `media_id + start_ms + end_ms` 表示，任何时候都不复制或转码成独立视频片段。
2. 用户字幕优先级高于机器转写；用户手动编辑优先级高于系统建议。
3. 断句不应仅按静音切分。系统应同时参考标点、语法候选边界、说话人变化、语速和停顿。
4. 切片过短时优先与相邻片段合并；切片过长时优先在意群边界提出拆分建议。
5. 转写不确定、字幕明显与音频不符或用户修改过的片段，均应保留“待核对”状态。

### 8.2 学习状态规则

| 操作 | 状态与复习行为 |
| --- | --- |
| 首次进入切片 | `new → practicing`。 |
| 标记“没听懂”或“没说顺” | 维持 `practicing`，次日到期。 |
| 完成盲听且完成至少一次跟读，并标记“已掌握” | 进入 `due`，按默认间隔安排复习。 |
| 连续完成长期复习 | 进入 `mastered`；仍可在 30 天后抽查。 |

### 8.3 隐私与内容规则

1. 原视频不上传、不共享、不进入公共素材库。
2. 用户调用云端转写前，必须明确同意上传提取后的音轨；传输使用加密连接。
3. 转写音轨及临时结果在任务完成后自动删除，最长保留 24 小时；失败任务也必须按相同策略清理。
4. 跟读录音默认只存设备；云端备份必须由用户单独开启。
5. 用户可在设置中删除账号关联的云端元数据与已备份录音；本地原视频由用户在设备上自行管理。

## 9. 技术方案与架构要求

### 9.1 推荐技术栈

| 层级 | 推荐选择 | 说明 |
| --- | --- | --- |
| 移动端 | React Native + Expo Development Build + TypeScript | 一套代码覆盖 iOS/Android；保留原生媒体扩展能力。 |
| 视频与音频 | `expo-video`、`expo-audio`；必要时以 Expo/React Native 原生模块接入 AVFoundation 与 Media3 | 支持本地播放、精确跳转、录音、蓝牙耳机和系统音频中断处理。 |
| 本地存储 | `expo-file-system` + `expo-sqlite` + SecureStore | 媒体与录音存文件系统，切片和复习记录存 SQLite，凭据安全保存。 |
| 云端基础服务 | Supabase（Auth、Postgres、Storage、Edge Functions） | 同步元数据和可选备份；使用行级权限隔离用户数据。 |
| 转写任务 | 可替换的云端转写 Provider + Python 异步 Worker | MVP 不自建 GPU；任务稳定后可评估自托管模型。 |
| 可观测性 | 崩溃追踪、性能埋点与匿名化产品事件 | 重点监测导入失败、转写失败、循环延迟和复习完成率。 |

### 9.2 架构边界

```text
移动端
├─ 本地媒体、字幕、录音、SQLite 学习记录
├─ 切片编辑与离线播放器
└─ 可选：提取音轨并提交转写任务

云端
├─ 账号、同步元数据、复习状态、可选录音备份
├─ 转写任务状态与短期签名上传地址
└─ 异步转写 Worker：音轨 → 时间轴/置信度/建议切片
```

### 9.3 转写接口要求

客户端不得依赖特定供应商返回格式。定义统一的 `TranscriptionProvider` 输出：

```ts
type TranscriptionResult = {
  language: 'en';
  segments: Array<{
    startMs: number;
    endMs: number;
    text: string;
    confidence?: number;
    words?: Array<{ text: string; startMs: number; endMs: number; confidence?: number }>;
  }>;
  nonSpeechRanges?: Array<{ startMs: number; endMs: number; type: 'music' | 'silence' }>;
};
```

说明：词级时间戳仅用于高亮和断句建议，不可被视为绝对准确的音素级对齐结果。

### 9.4 核心数据实体

| 实体 | 核心字段 | 说明 |
| --- | --- | --- |
| `user` | `id`、`sync_enabled` | 登录与同步设置。 |
| `media_project` | `id`、`local_uri`、`duration_ms`、`source_type` | 一条导入的本地媒体。 |
| `subtitle_source` | `project_id`、`type`、`language`、`version` | 用户字幕或转写结果。 |
| `segment` | `id`、`project_id`、`start_ms`、`end_ms`、`text`、`confidence`、`skip_type` | 虚拟练习切片。 |
| `practice_attempt` | `segment_id`、`mode`、`result`、`recording_uri`、`created_at` | 一次盲听或跟读行为。 |
| `review_schedule` | `segment_id`、`state`、`due_at`、`interval_days` | 间隔复习调度。 |
| `transcription_job` | `project_id`、`status`、`expires_at`、`provider` | 云端转写任务与清理记录。 |

## 10. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 离线 | 已导入且已处理的素材、切片、录音和复习队列在断网状态下可使用；联网后可增量同步。 |
| 性能 | 已缓冲素材从点击循环到开始播放的目标延迟不高于 300ms；切换相邻切片不应出现明显卡顿。 |
| 稳定性 | 来电、耳机断连、系统音频中断、录音权限拒绝和应用切后台时必须给出可恢复提示，不丢失已保存练习记录。 |
| 可访问性 | 主要按钮具备文本标签；字体可随系统字号放大；播放控制可单手操作。 |
| 安全 | 使用 HTTPS；服务端启用用户数据隔离；令牌不以明文写入普通本地存储。 |
| 兼容性 | MVP 测试最新两个主要 iOS 版本与主流 Android 设备；低端设备可禁用波形和高级动画。 |
| 可观测性 | 所有导入、转写、切片编辑、播放失败、录音失败和同步冲突均生成匿名化事件。 |

## 11. 成功指标与埋点

### 11.1 产品指标

| 指标 | 定义 | MVP 观察目标 |
| --- | --- | --- |
| 激活率 | 导入第一个项目并完成至少 3 个练习切片的用户占比 | 验证首日价值。 |
| 首次价值时间 | 从首次打开到完成第一条盲听加跟读的时长 | 越短越好，优先排查导入和处理阻塞。 |
| 周有效练习次数 | 每周有效练习不少于 10 分钟的会话数 | 北极星指标的组成。 |
| 复习完成率 | 到期切片中完成盲听或跟读的比例 | 验证间隔复习是否形成习惯。 |
| 切片修正率 | 用户合并、拆分或拖动过的系统切片占比 | 评估智能断句质量。 |
| 无字幕听懂率 | 用户在隐藏文本后标记“听懂”的比例 | 只作个人进步趋势，不作跨用户排名。 |

### 11.2 关键事件

`project_imported`、`subtitle_parsed`、`transcription_requested`、`transcription_completed`、`segment_edited`、`non_speech_marked`、`loop_started`、`recording_saved`、`blind_listen_completed`、`review_completed`、`sync_failed`。

## 12. MVP 验收场景

| 场景 | 验收结果 |
| --- | --- |
| 有字幕视频导入 | 用户导入 MP4 和 SRT 后，能在 60 秒内看到可编辑的句子切片并开始练习。 |
| 无字幕视频转写 | 用户明确同意后，客户端仅上传音轨；完成后获得待核对切片，且临时音轨在规定时间内删除。 |
| 切片修正 | 用户将两条短字幕合并并拖动尾部边界后，循环播放、字幕和复习均以新边界为准。 |
| 片头跳过 | 用户开启跳过非对白后，播放器跳过标为片头/纯音乐的区间，统计不计入该区间。 |
| 回声跟读 | 用户能在一个切片内完成“原句—留白—录音—回放”，录音可在离线状态下再次播放。 |
| 间隔复习 | 用户将句子标记为“没说顺”后，次日会在今日页看到该句；标记“已掌握”后按默认间隔延后。 |
| 离线恢复 | 用户断网并重启应用后，已处理素材可继续播放与练习；网络恢复后学习记录可同步。 |

## 13. 迭代计划

### 13.1 阶段 A：可用性原型

- 本地 MP4/MP3 + SRT/VTT 导入。
- 手动切句、单句循环、隐藏/显示字幕。
- 本地 SQLite 记录切片与练习状态。

**退出条件：** 试用者可以不依赖开发者协助，完成一次“导入—切句—练 5 句—次日复习”。

### 13.2 阶段 B：MVP 内测

- 云端转写任务、建议断句、低置信提醒。
- 跟读录音、非对白手动标记、可选登录同步。
- 今日复习、基础指标与崩溃追踪。

**退出条件：** 连续两周内，目标试用用户能稳定完成每周 3 次有效练习，且没有阻断性媒体或同步问题。

### 13.3 阶段 C：基于数据扩展

- 根据切片修正率优化断句与片头片尾识别。
- 根据复习完成率优化提醒、每日新增上限和复习节奏。
- 仅在需求被验证后加入离线转写、细粒度发音反馈和授权内容库。

## 14. 风险与待决策项

| 风险/问题 | 影响 | 应对 |
| --- | --- | --- |
| 机器转写与影视字幕不一致 | 学习者可能练错文本或时间点 | 将转写标记为待核对；始终提供编辑器；优先支持用户字幕。 |
| 不同设备的媒体格式和跳转精度不同 | 循环体验不稳定 | 限定首版支持格式；建立真机测试矩阵；为底层媒体控制预留原生模块。 |
| 云端转写成本、隐私与网络失败 | 影响激活和商业可行性 | 云端转写可选且按任务计量；只传音轨；记录任务成本；后续再评估自托管或离线模型。 |
| 片头音乐与对白配乐误判 | 可能跳过有效内容 | MVP 只做保守建议与用户修正；不在 P0 做强制自动跳过。 |
| 用户把学习变成机械刷次数 | 长期留存与学习效果下降 | 今日页突出到期复习、盲听与跟读；不展示夸张的“100 次完成度”。 |
| 版权与素材授权 | 平台合规风险 | 不托管公共影视内容；明确用户责任；引入授权内容前单独完成权利审查。 |
